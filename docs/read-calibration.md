# Source-read calibration

The production build (`teensy41`) excludes the benchmark and its buffers. Read-budget enforcement and the `d`, `D`, `p` diagnostic commands remain available.

## Build and run

- Normal firmware: `pio run -e teensy41`.
- Calibration firmware: `pio run -e teensy41_calibration`.
- Upload calibration firmware: `pio run -e teensy41_calibration -t upload`.
- Select a patch with `0.raw` fully cached in PSRAM (at least 4580 samples) and an active AudioTables wavetable bank.
- Send `b` over Serial to run the benchmark. Audio processing is suspended during acquisition; recording/conversion and metadata replacement are excluded.
- The tuning-tone button only controls the tuning tone; it no longer starts the benchmark.
- Rebuild and upload `teensy41` to return to normal firmware.

`lib/ReadBenchmark` is enabled by `LILLA_READ_BENCHMARK`, defined only by the calibration environment. It receives the cache and table owners from the main loop rather than depending on application globals.

## Measurement interpretation

Four individually timed reads per case at 600 MHz, over 10..4500 signed 16-bit samples. The benchmark compares exact reads (source address modulo 4 = 2) with expanded aligned reads, and reports cold and warm source-cache cases. Cache preparation and sample comparison are outside the timed interval. The results exclude interpolation, filters, envelope processing and other player work.

The production model uses the original `exact_mean_us` data: Flash seek/read, cold PSRAM zero-fill plus copy, and cold RAM2 copy. These are mean estimates, not worst-case guarantees. Recalibrate after changing clock, reader, alignment, memory placement or cache/access patterns.

The archived table below applies a cumulative maximum independently to each column. It is preserved for reference; the current affine models were fitted to the original measurements before that transformation, so fitting this table will not reproduce those coefficients exactly.

Current per-operation models in `PlayerReadBudget.h` (samples -> microseconds):

- Flash: `2.2526 + 0.385575 * samples`.
- PSRAM: `0.4655 + 0.059608 * samples`.
- RAM2: `0.1165 + 0.006258 * samples`.

The scheduler adds separate geometry and safety allowances. Its source-read budget remains 1800 microseconds.
